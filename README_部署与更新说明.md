# 训练簿 V16.4.3 · 在线 PWA 与自动验收版

## 目录
- `index.html`：主应用
- `manifest.webmanifest`：PWA 安装配置
- `sw.js`：离线缓存与自动更新
- `qa.html`：一键自动化验收（仅使用隔离测试数据）
- `icon-192.png` / `icon-512.png`：桌面图标

## 推荐部署：GitHub Pages
1. 在 GitHub 新建一个 **Public** 仓库（仓库名可用 `training-book`）。仓库只放应用代码，不要上传个人数据备份；免费 GitHub Pages 通常使用公开仓库。
2. 上传本目录中的全部文件到仓库根目录。
3. 在仓库 Settings → Pages 中，选择 Deploy from a branch，分支 `main`，目录 `/ (root)`，保存。
4. 等待 GitHub Pages 发布，得到固定 HTTPS 地址。
5. 打开 `https://<账号>.github.io/training-book/` 测试主应用。
6. 打开同一地址下的 `qa.html`，点击“运行一键验收”。

## 版本更新
- 后续将新版本文件提交到同一个仓库、同一目录。
- 保持正式数据键 `trainingBook_v3` 不变；不要更换域名/协议/端口/路径基址。
- `sw.js` 中的 `CACHE_NAME` 每次发布递增，例如 `trainingbook-pwa-v16`。
- Service Worker 会安装新缓存、接管页面并刷新到新版本。
- 同一 HTTPS 来源下的 localStorage 数据会跨版本保留，不需要每次导出/导入。

## 数据边界（重要）
- 这是**本地优先 PWA**：数据保存在当前浏览器/设备的本地存储中。
- 在线访问和自动更新不等于云端同步；不同设备、不同浏览器的数据不会自动合并。
- 从旧的 `file://` 本地 HTML 迁移到新的 HTTPS 地址时，浏览器存储隔离，需做**一次性**旧版 JSON 导出并在新站导入。此后同一网址更新无需重复导入。
- 仍建议偶尔导出备份；卸载浏览器、清理网站数据或换设备可能导致本地数据丢失。
- 自动验收页面使用独立测试键 `trainingBook_v3_test`，不会覆盖正式键 `trainingBook_v3`。

## 当前限制
- GitHub Pages 发布需要用户自己的 GitHub 账户授权/仓库操作。本版文件部署到 GitHub Pages 后即可获得公开 HTTPS 网址。
- 如需真正的跨设备云同步，需要另行配置登录身份与云数据库；本版没有伪装成已实现云同步。


## V16 更新内容：国内动作教学与替代动作
- 四套训练计划的主动作教学页增加国内视频教学入口，统一使用哔哩哔哩。
- 已匹配到具体公开视频的动作使用 B 站外链播放器；若内嵌播放器受浏览器、登录状态或平台策略影响，可点击“打开B站原视频”。
- 暂未核验到稳定单条视频的动作，提供按动作名称生成的 B 站站内搜索入口，不编造 BV 号。
- 每个主动作增加至少两个替代动作；每个替代动作均有独立的 B 站教学搜索入口。
- 保留现有训练记录、饮食、提醒、健康许可和本地数据键，不更换正式数据存储键 `trainingBook_v3`。
- 发布时更新 Service Worker 缓存名为 `trainingbook-pwa-v16`。

### 视频来源说明
B 站官方外链播放器使用 `https://player.bilibili.com/player.html?bvid=...` 形式。公开视频的播放仍可能受作者删除、地区/账号权限、浏览器策略等因素影响，因此应用保留打开 B 站原视频的备用入口。


## V16.4 更新内容：日期一致性与数据导入保护
- 日程、周视图和训练记录日期统一按设备本地日期计算，避免 UTC 时区导致跨日错位。
- 导入备份前校验核心数据结构；无效文件不会写入当前数据。
- 导入前显示将替换的数据数量，并要求二次确认。
- 导入写入失败时保留原有本地数据；成功后补齐可选数据结构。
- 自动验收增加本地日期边界与备份结构校验。


## V16.4.2 更新内容：主动作视频补齐与验收加严
- 为四套训练计划中的17个主动作补齐具体B站内嵌教学视频；对变式动作在标题或说明中标注动作模式差异。
- 自动验收不再把“存在视频占位/搜索入口”视为主动作视频通过，改为检查每个主动作均存在B站播放器 iframe。
- 替代动作继续逐卡检查内嵌播放器。
- Service Worker 缓存版本升级为 trainingbook-pwa-v16.4.2。
- 视频链接已按公开页面检索匹配；实际播放仍需在用户设备浏览器中逐条验证，不能仅凭 iframe 存在判定可播放。


## V16.4.3 更新说明
- 正式版固定使用 GitHub Pages HTTPS 地址；后续代码提交由 Pages 自动发布。
- 新增 GitHub Actions 浏览器自动验收：主程序、QA 页面、PWA 配置等相关文件变更时，在 main 推送和 Pull Request 中运行隔离测试。
- 自动验收通过后才可将该次代码变更视为通过 QA；Pages 发布成功与浏览器 QA 结果分别显示。
- QA 使用独立测试存储键 `trainingBook_v3_test`，不读取或覆盖正式训练数据。
- 正式数据仍保存在当前设备浏览器本地；本次更新不提供跨设备云同步。
